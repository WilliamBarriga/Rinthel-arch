# dev-ui
Browser app of `dev`: the page `diagrams dev` serves at `/` and `/_dev-ui/*` (user guide: `docs/guide/dev-ui.md`).

## What it does
- `browser/` by feature (one folder each); `dev.tsx` boots and `dev-ui.tsx` only assembles. `frame/providers.tsx` wraps frame and canvas; the frame (`frame/frame.tsx`, chrome state with `useChrome()`, `--ui-*` tokens under `.ui-chrome` in `tokens.css`) defines no domain types, and outside `frame/` only types of its context are imported.
- Seams: the tab registry `frame/tabs.tsx` (a new panel receives no props) and `useDevUi()` from `frame/context.ts` (`goToView`, `openTab`, `notify`, `write`, `openCode`...), with `useEditorChannel()` and `useThemePreview()` apart. Read by version: `frame/use-read-by-version.ts` (discards stale responses; `useInspectByVersion`). Single listbox: `frame/use-listbox.ts` (`aria-activedescendant`; used by the View index, where the choice follows the arrows, and by the Theme gallery). The View goes in `#view=<id>` (`canvas/dev-ui-hash.ts` translates the shell's `p` key).
- Commands: a single registry `COMMANDS` (`commands/registry.ts`) from which come shortcuts (a single listener; scopes in `keys.ts:resolveKey`), the Finder (Mod+K) and help (`?`). A new command is an entry `{ id, name, keys, scope, run(devUi) }`; a button announces it with `<ButtonWithShortcut command="id">`.
- Tour (`tour/`): "Start here" coachmarks, the non-modal `tour` dialog (the highlighted area stays live; a layer with the area cut out blocks the dimmed rest) of the frame (`openDialog('tour')`, command "View tour" and a button in the `?` help). `stops.tsx` is the fixed script, read from the Workspace when the tour opens; `seen.ts` remembers in `localStorage` (memory only if it throws, as over `file://`) that the "1-minute tour" pill was used or dismissed.
- Writing (`writing/writing.ts`, `write` from `useDevUi()`): the single path of actions that write (move, order, undo, redo, jump, set Theme, apply `fix`); owner of the current version, of the 409 (reloads and warns; retries once only if the request asks for it, like `issues/apply-fix.ts`) and of the notice; it flushes the editor save before moving the File history. The editor (`editor/`, CodeMirror 6) saves on its own: `save.ts:createSaver` (400 ms debounce, `aunqueNoCompile`) and `reconciliation.ts` (`threeWayMerge`) against external writes.
- History, Diffs and agent activity are per-client stores (`store.ts`, WeakMap; not in `useDevUi`): they are created on connect so the first SSE event is not lost. The projection of the Diff onto the canvas is pure (`diff/projection.ts`). `browser/client.ts`: the only piece with routes; validates everything with the protocol schemas (a malformed 2xx is a failure), never throws (`Read<T>`) and shares a single SSE connection (`listen`). `dev-ui/protocol` re-exports the protocol of `canonical`. `dev-ui/contract` (tests only): `testDevContract(create)`, `inMemoryDev` (the Live workspace of `session` over `inMemoryPort`; only the transport is fake) and `eventsOverFetch`.
- Export (`diagrams export`): the same app in read-only mode. `mode` (`frame/mode.ts`, prop of `<DevUi>`, `useDevUi().mode`) is the single flag: components read the derived capability `useDevUi().canWrite` (`canWriteIn`) instead of comparing the mode, registry entries with `devOnly` (tabs, top bar pills, commands, tour stops) are left out (and `exportOnly` ones only show in the export), and the canvas and the Themes gallery do not write. `<DevUi client>` replaces `fetch` and `events` with the read-only client (`export/read-only-client.ts`) over the data of `src/export.ts` (`captureExport`, through the `dev` API). The page is `export/page.tsx`; `src/export-html.ts` (`exportHtml`) inlines it with the Worker code and the data; `export/layout.ts` starts the Worker from a Blob or runs it on the main thread.
- Build (`tsup` + `scripts/build.ts`, which calls `dev-ui/build`, the same entry the bench uses): `dist/dev-ui/` with `index.html`, `page.js` (the editor and the dialogs in `chunks/` on demand), `worker.js` (zod replaced by `worker/inert-zod.ts`), `style.css` and `export.js` (the export page: one IIFE without the editor nor ELK); `devUiAssets()` gives their paths and `devUiFolder()` the folder. It also regenerates `browser/editor/keywords.ts` from the `dsl` grammar (committed; do not edit by hand).

## What it does not do
Serves nothing and does not touch the Workspace (server, disk and Theme `.tsx` are `cli`'s; the `/api/*` routes, `session`'s); does not draw (`render`, `shell`). Not in `NUCLEO`: it uses DOM, `fetch` and `EventSource`. No Tailwind nor shadcn: Base UI (pinned version) and own CSS.

## Depends on
`canonical`, `render`, `shell`, `session` (only `inMemoryDev`) and `layout` (today only in tests). External: `react`, `react-dom`, `zod`, `@base-ui/react`, CodeMirror 6 (`@codemirror/*`, `@lezer/highlight`; pinned versions); `esbuild` in the build; `vitest` as optional peer of `dev-ui/contract`.

## Entry file
`packages/dev-ui/src/index.ts` (Node, with the export), `packages/dev-ui/src/protocol.ts`, `packages/dev-ui/src/contract.ts` and `packages/dev-ui/src/build.ts`; the page boots in `packages/dev-ui/browser/dev.tsx` and the Worker in `packages/dev-ui/browser/worker/worker.ts`. Iterate: rebuild and reload.

`docs/adr/0004-pnpm-monorepo-and-packages.md` (`dev-ui` amendment) and `docs/adr/0007-interaction-and-edit-protocol.md`.

## Test
`pnpm --filter dev-ui test`: pure functions, the contract against `inMemoryDev` and the app in jsdom (`test/ui-helpers.tsx:mountDevUi`, queries by role; `maxWorkers: 2`, fake timers for debounce and highlighting; tests do not import internal UI constants). Every new `dev` route goes into the contract. `cli` runs the same contract against the real `dev` and the single Chromium end-to-end (`packages/cli/test/e2e-estudio.test.ts`); marker position, scroll and drags are tested only there.
